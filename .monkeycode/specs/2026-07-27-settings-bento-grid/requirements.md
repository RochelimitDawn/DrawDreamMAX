# 设置页 Bento Grid 需求

## 简介

设置页需要在桌面端和平板横向视口中提供清晰的主题分组、优先级层级和高效的配置操作。移动端继续使用现有的“分区列表 → 详情下钻”交互。

## 术语

- **Bento Grid**：使用不同卡片跨度组织并列设置主题的网格布局。
- **设置主题**：通用、API、界面、阅读、对话、高级和关于等导航分区。
- **移动端布局**：宽度小于 `900px` 时使用的分区列表和详情页布局。

## 需求

### 需求 1：桌面设置主题布局

**用户故事：** 作为桌面用户，我希望设置主题按优先级组织在 Bento 网格中，以便快速扫描和定位配置。

#### 验收标准

1. 当视口宽度达到 `900px` 时，设置页应显示侧边主题导航和 Bento 内容画布。
2. 当设置主题包含核心操作时，主题内容应占据完整内容宽度。
3. 当设置主题包含并列的短配置项时，主题内容应使用两列卡片展示。
4. 当用户切换设置主题时，内容画布应保留统一间距、圆角和边界层级。

### 需求 2：桌面与平板可读性

**用户故事：** 作为桌面或平板横屏用户，我希望设置卡片保持可扫读，以便完成配置时减少视觉跳转。

#### 验收标准

1. 当卡片展示标题、说明和控件时，标题应位于说明之前，控件应保持可操作区域。
2. 当 API 渠道数量增加时，渠道卡片应以两列网格排列并保持名称、状态和操作可见。
3. 当 API 编辑区包含多个字段时，字段应在两列网格中排列，操作按钮应位于完整宽度区域。
4. 当内容高度超过视口时，侧边导航和内容区域应保持可访问。

### 需求 3：移动端布局兼容

**用户故事：** 作为手机用户，我希望继续使用熟悉的设置下钻流程，以便在窄屏中逐项配置。

#### 验收标准

1. 当视口宽度小于 `900px` 时，设置页应继续使用现有的分区列表和详情下钻结构。
2. 当用户进入移动端设置详情时，返回入口应保持可见。
3. 当移动端展示 API 渠道时，渠道名称、状态和操作应保持可见并适应窄屏宽度。

### 需求 4：验证与发布

**用户故事：** 作为维护者，我希望设置页变更经过构建验证并记录在规范文档中，以便后续移动端发布保持可追溯。

#### 验收标准

1. 当设置页代码发生变更时，项目应通过 `npm run build`。
2. 当移动端交付包含设置页变更时，项目应通过 `npm run mobile:smoke`。
3. 当发布版本确定时，移动端规范应记录桌面 Bento 布局和移动端兼容边界。
